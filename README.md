# Intrusion Detection System

Network intrusion detection pipeline for multiclass classification,
using preprocessing code generated by an LLM.

## Repository structure

```text
.
├── experiments/
│   ├── run.py                  # Entry point
│   ├── config.py               # Configuration loading and validation
│   ├── pipeline.py             # Pipeline orchestration
│   └── validation_suite.py     # Validation selection and TEST evaluation
├── data/
│   ├── preprocessing/          # Dataset cleanup, traditional and LLM preprocessing
│   └── feature/                # Feature selection and extraction
├── llm/                        # API client, prompts, code generation and validation
├── models/base_model.py        # Classifier training and evaluation
├── datasets/                   # TRAIN/TEST CSV files
├── generated/                  # Generated code and history.json
├── rejected_artifacts/         # LLM responses that failed validation
├── text_files/                 # Reports and validation_splits/ manifests
├── .env.example                # Configuration template
├── .env                        # Local runtime configuration; ignored by Git
└── requirements.txt            # Python dependencies
```

`generated/` and `rejected_artifacts/` are created when needed. The local dataset
folder contains UNSW-NB15 and NSL-KDD CSV files. Datasets and generated outputs
are excluded from Git by `.gitignore`.

## Pipeline

1. Load `.env` and official TRAIN. Create a fixed split of approximately 80%
   inner TRAIN and 20% validation (VAL), using seed 42. Save the split for reuse
   and keep rare classes represented in inner TRAIN.
2. Apply dataset-specific cleanup and target normalization.
3. Preprocess and select features according to the run mode:
   - **Traditional:** encode with OneHotEncoder, scale with MinMaxScaler,
     rank features using RF+MI, filter Pearson redundancy, and select K
     using LightGBM on VAL.
   - **LLM:** generate or load validated preprocessing and feature-selection
     code. Lock features using the unresampled candidate, then use LightGBM
     on VAL to select `none`, `mild`, or `moderate` resampling when available.
4. Lock the selected features and policy, fit classifiers on inner TRAIN,
   and evaluate on official TEST. Read TEST only after validation selection;
   do not refit on the full TRAIN dataset.
5. Save Accuracy, Precision, Recall, F1, execution time, and API usage.
   LLM runs report means and standard deviations across successful artifacts.

Classifiers: Decision Tree, Random Forest, KNN, MLP, Bernoulli NB,
XGBoost, LightGBM, and CatBoost.

## Setup and execution

Run commands from the repository root. For initial setup:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

Edit `.env` for your dataset and run mode, then start the pipeline:

```bash
.venv/bin/python experiments/run.py
```

To capture console output:

```bash
mkdir -p text_files
.venv/bin/python -u experiments/run.py > text_files/run.log 2>&1
```

### Traditional preprocessing

Minimal configuration for UNSW-NB15 binary classification, without API calls:

```env
DATASET_NAME=UNSW_NB15
TRAIN_PATH=./datasets/UNSW_NB15_training-set.csv
TEST_PATH=./datasets/UNSW_NB15_testing-set.csv
CLASSIFICATION_TYPE=binary
TARGET_COLUMN=label
MODEL_ID=traditional
USE_LLM=true
N_RUNS=1
K_VALUES=24,26,28,30
```

`MODEL_ID=traditional` selects this mode. `USE_LLM` does not trigger API calls
in this mode. Clear any previous `GENERATED_FILE` or `GENERATED_FILES` values.

### Generate preprocessing with an LLM

Keep the dataset settings above and replace the following settings.
Use a model ID supported by your provider:

```env
LLM_PROVIDER=yescale
BASE_URL=https://api.yescale.io
API_KEY=your-api-key
MODEL_ID=claude-sonnet-4-6
LLM_MAX_TOKENS=8192
USE_LLM=true
N_RUNS=3
K_VALUES=auto
```

For an OpenAI-compatible endpoint, set `LLM_PROVIDER=openai` and configure
`BASE_URL`, `API_KEY`, and `MODEL_ID` for that endpoint. Use the same run command.

### Reuse generated code

Keep an LLM model ID and select an existing file in `generated/`:

```env
USE_LLM=false
N_RUNS=1
GENERATED_FILE=artifact_01.py
```

For multiple runs, unset `GENERATED_FILE` and provide distinct filenames:

```env
USE_LLM=false
N_RUNS=3
GENERATED_FILES=artifact_01.py,artifact_02.py,artifact_03.py
```

Replace these example names with actual generated filenames. This mode still
runs VAL/TEST evaluation but makes no API calls. Generate artifacts before
attempting to reuse them.

## Configuration reference

Settings are loaded from `.env`; values in that file override shell environment
variables.

| Variable | Meaning |
| --- | --- |
| `DATASET_NAME` | `UNSW_NB15`, `NSL_KDD`, `CIC_IDS_2017`, or `BotNetIoT_L01`. BotNetIoT currently has a traditional preprocessing path only. Supply your own CSV files for CIC/BotNet. |
| `TRAIN_PATH`, `TEST_PATH` | Required paths to pre-split TRAIN/TEST CSV files. Relative paths are resolved from the working directory. |
| `CLASSIFICATION_TYPE` | `binary` or `multiclass`; default: `binary`. |
| `TARGET_COLUMN` | Target column after dataset cleanup; default: `label`. UNSW-NB15/NSL-KDD use `label` for binary and `attack_cat` for multiclass. NSL-KDD multiclass normalizes this setting to `attack_cat`. |
| `MODEL_ID` | `traditional` or an API model ID. Identifies the code-generating LLM, rather than an evaluation classifier. Default: `traditional`. |
| `USE_LLM` | In LLM mode, `true` generates fresh code and `false` loads existing code; default: `true`. |
| `N_RUNS` | Number of generated or reused artifacts to evaluate; integer >= 1, default: `1`. Traditional mode supports only `1`. |
| `GENERATED_FILE` | Filename within `generated/` when reusing one artifact. |
| `GENERATED_FILES` | Comma-separated filenames. For `N_RUNS > 1`, provide exactly `N_RUNS` distinct names. Do not combine with `GENERATED_FILE`. |
| `K_VALUES` | Traditional mode: distinct positive integers; `auto` uses `24,26,28,30`. Current LLM mode selects K internally, so keep `auto`. |
| `LLM_PROVIDER` | `openai` / `openai-compatible` or `anthropic` / `yescale`; default: `openai`. |
| `BASE_URL`, `API_KEY` | Endpoint and API key for code generation. Provider-specific fallbacks: `ANTHROPIC_BASE_URL`/`OPENAI_BASE_URL` and `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`. |
| `LLM_MAX_TOKENS` | Maximum output tokens for Anthropic/YesScale; default: `8192`. |
| `PRICE_PROMPT_PER_1M_USD`, `PRICE_COMPLETION_PER_1M_USD` | USD per million tokens used for cost reporting; default: `0`. Prices are not fetched from the provider. |
| `REDUCTION_METHOD`, `RESAMPLING_SELECTION_K` | Legacy settings: loaded for compatibility but do not control the current main pipeline. |

For NSL-KDD, set `TRAIN_PATH=./datasets/KDDTrain+.csv` and
`TEST_PATH=./datasets/KDDTest+.csv`. For UNSW-NB15 multiclass, set both
`CLASSIFICATION_TYPE=multiclass` and `TARGET_COLUMN=attack_cat`.

## Outputs

- `generated/*.py`, `generated/history.json`: generated preprocessing and
  feature-selection modules, with generation history.
- `text_files/*.txt`: reports. LLM mode also saves `*.json` manifests containing
  configuration, selected policies, metrics, timing, and API usage.
- `text_files/validation_splits/*.json`: fixed TRAIN/VAL partitions and dataset
  integrity metadata.
- `rejected_artifacts/`: diagnostics for generated responses that failed validation.
